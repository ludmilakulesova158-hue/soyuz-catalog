## Логика

1. Читает `meta.json` из бакета (там лежит `feedEtag` прошлого успешного обновления).
2. Запрашивает фид условно (`If-None-Match: <feedEtag>`). Ответ `304` — фид не менялся,
   скачивания 2 МБ нет, пишется только `status.json` (heartbeat) и выход.
   Пропуск допускается, только если совпали и `generation-date`, и `ETag` (правка объекта
   без смены даты не теряется).
3. Раз в 24 часа — режим `recheck`: фид читается без `If-None-Match` (страховка от ложного `304`),
   но сравнение по хешам работает как обычно. Отметка хранится в `manifest.json` (`recheckAt`).
   Ручной запуск: `invoke recheck`.
4. При изменении парсит фид, пишет изменившиеся `objects/<id>.json` (8 потоков), затем `cards.json`
   (gzip, `Content-Encoding: gzip`) и `meta.json` последней — meta служит «коммитом»
   (в ней сохраняется новый `feedEtag`).
5. Удаляет из бакета объекты, выпавшие из фида (по манифесту).
6. Защита: 0 объектов или падение количества больше чем в 2 раза — данные не перезаписываются.
   При недоступности прямого фида — повтор через `translate.goog`.

Кэш: `meta.json` и `cards.json` — 60 с, объекты — 21600 с (6 часов; адреса содержат `?v=<generated>`).

## Нагрузка со стороны сайта

- кэш каталога в localStorage — 10 минут;
- фоновый опрос `meta.json` — 10 минут, только когда вкладка активна;
- возврат к вкладке (`focus`/`visibilitychange`) — не чаще раза в 60 секунд;
- открытие страницы: 1 запрос `meta.json` + 1 `cards.json` (+ файл объекта при открытии карточки).

## Отказоустойчивость сайта

После обмена (14.11.2026) главная берёт базу из Yandex (`data-data-base`), а `CD` всегда указывает
на GitHub: если Yandex недоступен (лимит гранта, сбой аккаунта), страница автоматически грузит
данные из GitHub и продолжает работать (проверено блокировкой запросов к `storage.yandexcloud.net`).
Страница `/catalog-v3` намеренно оставлена на GitHub-базе как резервный вариант.

**GitHub-резерв поддерживается живым:** после каждого обновления функция тем же прогоном делает
один коммит в репозиторий через Git Data API (`Trees` со встроенным контентом → `commit` → `ref`),
включая удаление выпавших объектов. Это 4 запроса к API на обновление, без GitHub Actions.
Если дерево не изменилось (например, суточный `recheck` при тех же данных), коммит не создаётся
(`skipped: tree unchanged`) — история не засоряется.
Workflow `update-catalog` и `debug-feed` отключены (14.11.2026), чтобы не перетирать свежие данные
старыми; код воркфлоу остаётся в репозитории.
Переменная функции `GH_TOKEN` — PAT с правами `repo`, лежит в переменных окружения функции
(виден тем, у кого есть доступ к функции; при передаче проекта клиенту — перевыпустить).

Блоки собираются скриптом `yc/build-blocks.cjs`:
- `catalog-block.main-yc.html` — главная (Yandex + fallback GitHub, заголовок `h2`);
- `catalog-block.v3-gh.html` — `/catalog-v3` (GitHub, заголовок `h1`).

## Обновление кода

Инструменты лежат в репозитории (секретов в них нет):

- `yc/tools/yc.cjs` — IAM по ключу SA, функции, версии, триггеры, ручной запуск;
- `yc/tools/s3.cjs` — бакет: создать, ACL, CORS, список, чтение/запись файлов;
- `yc/tools/tilda.cjs` — вызов MCP-инструментов Tilda (обновление блока, публикация).

Сеть в `yc.cjs` — через `node:https`, потому что глобальный `fetch` на рабочей машине нестабилен
к `*.yandex.net` (connect timeout), хотя `curl` работает.

```
# с переменными окружения нужного аккаунта
$env:YC_KEY="...authorized_key.json"; $env:YC_FOLDER="b1gabnr36mv0oqh9rdc6"; $env:YC_SA="aje0s1lt817bvb09cdq5"
node yc/tools/yc.cjs whoami
node yc/tools/yc.cjs versions
node yc/tools/yc.cjs fn-create soyuz-catalog
node yc/tools/yc.cjs deploy --env-file=<env.json>
node yc/tools/yc.cjs trigger-create soyuz-catalog-timer
node yc/tools/yc.cjs invoke recheck
node yc/tools/yc.cjs dump-env <env.json>      # снять переменные текущей версии
```

`deploy` берёт за основу активную версию функции (runtime, память, таймаут, SA, переменные);
для новой функции нужны `YC_SA` и `--env-file`. Архив:
`Compress-Archive -Path yc\index.js,yc\package.json -DestinationPath yc\fn.zip`
(`package.json` содержит `"type": "module"`). `node_modules` не нужны.

Бакет (новый или при переносе):

```
node yc/tools/s3.cjs mkdir soyuz-catalog-data-kaluga
node yc/tools/s3.cjs acl  soyuz-catalog-data-kaluga public-read
node yc/tools/s3.cjs cors soyuz-catalog-data-kaluga
```

Блоки собираются скриптом `yc/build-blocks.cjs` (адрес бакета — константа в нём):
- `catalog-block.main-yc.html` — главная (Yandex + fallback GitHub, заголовок `h2`);
- `catalog-block.v3-gh.html` — `/catalog-v3` (GitHub, заголовок `h1`).

Обновление блока на главной: собрать HTML, затем `tilda.cjs call update_record <args.json>`
(`only_field: "code"`, `fields.code`) и `call publish_page`. Аргументы собираются скриптом из файла,
чтобы 63 КБ HTML не гонять через чат.

## Проверка

- `status.json` — отметка последнего запуска (`checkedAt`, `result`, `written`, `removed`;
  `reason: "304"` — фид не менялся).
- Ручной запуск: `node yc/tools/yc.cjs invoke` (обычный), `invoke recheck` (суточная страховка),
  `invoke force` (перезаписать всё, игнорируя манифест).
- Флаги передаются в теле события (`{"recheck":true}`), функция читает и `body`.

## Важно: доступ к бакету

- Публичное чтение сделано **ACL** (`x-amz-acl: public-read` через `PUT ?acl`) — права владельца
  при этом сохраняются, запись/список работают.
- **Не добавлять bucket policy одновременно с ACL.** Политика в Object Storage авторитетная:
  если она разрешает только `GetObject`, то владелец теряет запись, список и ACL — бакет
  становится доступен только на чтение, и вернуть права можно лишь из консоли.
- Роль `editor` не даёт менять ACL бакета, нужна `storage.admin`.

## Стоимость

- Вызовы функции: 5 760/мес (при `*/15`) — бесплатный лимит 1 000 000.
- Память-время: ~1 500 ГБ×с/мес — бесплатный лимит 10 000.
- Входящий трафик не тарифицируется; при `304` скачивания фида нет вообще.
- `cards.json` хранится в gzip: 163 КБ -> 33 КБ, трафик посетителям меньше в ~5 раз.
- Платное по сути только исходящий трафик посетителям и запросы к бакету:
  при ~100 просмотрах в день ориентировочно 0,5–1 ₽/мес, при 300 — ~2–2,5 ₽/мес.
- PUT: ~290/сутки (heartbeat 96 + ~200 на изменения) ≈ 0,14 ₽/мес; суточный `recheck`
  добавляет ~3–4 PUT и 2 МБ трафика в сутки (~0,09 ₽/мес).
- Грант 4 000 ₽ действует 60 дней с активации (до ~12.01.2027) — расход за это время ~2 ₽;
  после — списывается с карты клиента (0,5–2,5 ₽/мес).
