# soyuz-catalog

Каталог объектов АН «Союз» (Калуга): каждые 30 минут GitHub Actions забирает
XML-фид JoyWork и публикует компактный JSON для сайта soyuzkaluga.ru.

## Что здесь

- `scripts/convert.mjs` — конвертер Yandex Realty XML → JSON (без зависимостей)
- `.github/workflows/update.yml` — автообновление по расписанию
- `data/` — сгенерированные данные (обновляются роботом)

## Yandex Cloud: робот в РФ (14.11.2026)

Причина: GitHub Actions ходит с зарубежных IP, а joywork.ru их периодически режет; крон GitHub
душится и даёт разрывы 2–4 часа. Локальный робот на ПК удалён (14.11.2026).

- **Бакет** `soyuz-catalog-data` — публичное чтение, CORS `*`, кэш 60 с (`meta.json`, `cards.json`)
  и 3600 с (объекты). Данные в РФ, ПДн агентов за границу не уезжают.
- **Функция** `soyuz-catalog` (Node.js 22) — тот же конвертер. Если фид не менялся, запрос уходит
  условный (`If-None-Match` по сохранённому `feedEtag`) и сервер отвечает `304` без передачи 1,7 МБ;
  при неизменном `generation-date` данные не перезаписываются (обновляется только `status.json`).
- **Триггер** `soyuz-catalog-timer`, cron `*/15` (фактическая задержка запуска до ~1 минуты).
  Раз в 5 минут не нужно: условный запрос и так почти ничего не стоит, но 15 минут выбраны
  как компромисс по свежести и расходу.
- **Отказоустойчивость:** если Yandex недоступен (лимит гранта, сбой), блок на главной
  автоматически переключается на GitHub-данные — страница продолжает работать.
- **GitHub-резерв актуален:** после каждого обновления функция делает один коммит в репозиторий
  (Git Data API, без Actions), включая удаление выпавших объектов. GitHub Actions отключены
  (14.11.2026) — они не забирают фид с зарубежных IP и перетирали бы свежие данные старыми.
- **Экономия запросов:** на странице кэш каталога 10 минут, фоновый опрос 10 минут, возврат
  к вкладке обновляет не чаще раза в минуту; объекты в бакете кэшируются 6 часов
  (адреса содержат `?v=<generated>`), `meta.json`/`cards.json` — 60 секунд.
- Публичный URL: `https://storage.yandexcloud.net/soyuz-catalog-data/`
- Подробности и идентификаторы: `yc/deploy.md`, исходник функции — `yc/index.js`.
- **Каталоги поменяны местами (14.11.2026):** главная `5793809001` берёт данные из Yandex
  (запасной источник — GitHub), `/catalog-v3` (`386001209`) — из GitHub. База данных в блоке
  задаётся атрибутом `data-data-base` у `#vb-cat-root`; на главной заголовок каталога — `h2`.

## Автономная работа (15.11.2026)

Робот переведён в режим без ручного вмешательства:

- **Запись только изменившихся объектов.** Функция хранит `manifest.json` (id -> sha1 содержимого).
  На каждом обновлении пишутся только новые и изменённые файлы, остальные не трогаются; объекты,
  выпавшие из фида, удаляются по манифесту. Полная сверка с хранилищем — при первом запуске,
  по `force` и раз в сутки.
- **Сокращение базы более чем вдвое** больше не требует ручного запуска: изменение фиксируется
  в `pending.json`, и если следующий прогон его подтверждает, обновление применяется само.
  Если фид вернулся к норме — данные не меняются.
- **Сбои видны**: любая ошибка пишется в `status.json` (`result: error` или `hold`)
  с причиной, а не остаётся молчанием.
- **Расход**: было ~18,8 тыс. PUT в сутки (~5 ₽/сутки, всё в гранте) — стало ~200 PUT в сутки
  (~0,06 ₽/сутки).
- Проверено на отдельном тестовом бакете: полная запись -> повтор (304) -> удаление 5 объектов
  (`written 0`, `removed 5`) -> сокращение базы (`hold`, данные сохранены) -> подтверждение
  (применено, `removed 12`). Тестовый бакет удалён.

## Надёжность и трафик (16.11.2026)

- **Суточная страховка `recheck`.** Раз в 24 часа (поле `recheckAt` в `manifest.json`) функция
  перечитывает фид, игнорируя `ETag`, но с обычным сравнением по хешам. Защита от случая, когда
  сервер фида отвечает `304` при реальных изменениях, и от «залипшего» `generation-date`.
  Проверено ручным запуском: `written 0`, GitHub-коммит не создан, `recheckAt` обновился.
- **Правка без смены `generation-date` больше не теряется.** Пропуск обновления теперь только
  если совпали и дата генерации, и `ETag`.
- **`cards.json` отдаётся сжатым** (`Content-Encoding: gzip`): 163 КБ -> 33 КБ, экономия трафика ~5×.
  Браузер распаковывает прозрачно; в GitHub-зеркале файл остаётся обычным JSON.
- **Пустые коммиты в GitHub убраны**: если дерево не изменилось, `syncGitHub` возвращает
  `skipped: true`. Это важно именно для суточного `recheck`.
- **Стоимость** после этих правок: PUT ~290/сутки (0,14 ₽/мес), трафик при 100 просмотрах/сутки
  ~0,2 ГБ (0,3 ₽/мес) за счёт gzip; функция и логи — копейки. Ориентир: 0,5–2 ₽/мес
  при 100–300 просмотрах в сутки. Грант 4 000 ₽ действует 60 дней (до ~12.01.2027).
- **Инструменты администрирования теперь в репозитории:** `yc/tools/yc.cjs`
  (`whoami | versions | trigger | deploy | invoke recheck`). Сеть в нём идёт через `node:https`:
  глобальный `fetch` на этой машине нестабилен к `*.yandex.net` (connect timeout), тогда как
  `curl` и сырой `https` работают. Ключ SA — `C:\Users\admin\Downloads\authorized_key.json`.
- Деплой: собрать `yc/fn.zip` из `index.js` + `package.json`, затем `node yc/tools/yc.cjs deploy`.
